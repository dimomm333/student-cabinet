# Личный кабинет студента (ЛКС)

**Единая университетская информационная система для студентов и сотрудников**

Конкурсный веб-проект на примере вымышленного **Северного университета**.
Расписание, успеваемость, сессия, заявления и внутренние сервисы — в одной системе с разграничением доступа по ролям.

## Что умеет система

| Модуль | Возможности |
|:--|:--|
| **Расписание** | Пары по группам и преподавателям, числитель/знаменатель, замены, отмены и проверка конфликтов. |
| **БРС и журнал** | Дисциплины, модули, баллы, лабораторные и домашние задания, посещаемость, итоговые результаты. |
| **Сессия** | Зачёты и экзамены, учёт результатов и допусков. |
| **Услуги** | Электронные заявления, обработка обращений сотрудниками и история статусов. |
| **Общежитие** | Учёт проживания, комнат и мест, платежей и заявок на ремонт. |
| **Физкультура** | Спортивные группы, запись, посещаемость, нормативы, отработки и зачёт по БРС. |
| **Портфолио** | Достижения студента, вложения и проверка записей деканатом. |
| **Обходной лист** | Согласование подразделений, замечания, итоговая проверка и защищённый PDF. |
| **Электронный пропуск** | Пропуск студента с QR-кодом, выдача, отзыв и проверка уполномоченными сотрудниками. |
| **Полезное** | Каталог инструкций, справочных материалов и ссылок с редактированием через кабинет администратора. |
| **Уведомления и новости** | Объявления, уведомления и информация о действиях в системе. |

Содержимое кабинетов зависит от роли и назначенных прав. Некоторые модули требуют отдельной подготовки демонстрационных данных: наличие страницы **не означает**, что база уже заполнена.

## Кабинеты и роли

В приложении используется общая авторизация, но интерфейсы и разрешения разделены.

| Роль | Маршрут | Для чего нужен кабинет |
|:--|:--|:--|
| **Студент** `STUDENT` | `/dashboard` | Личное расписание, оценки, сессия, услуги, общежитие, физкультура, портфолио. |
| **Преподаватель** `TEACHER` | `/teacher` | Расписание, учебные материалы, журнал, оценки, сессия и связанные занятия. |
| **Деканат** `DEANERY_STAFF` | `/deanery` | Учебные данные, допуски, заявления, расписание и проверка достижений в пределах назначений. |
| **Технический сотрудник** `TECHNICAL_STAFF` | `/staff` | Технические обращения, служебные задачи, пропуска и другие разрешённые операции. |
| **Администратор** `ADMIN` | `/admin` | Настройка и сопровождение данных, справочников, новостей и отдельных университетских процессов. |

Доступ проверяется **на сервере**: скрытие пункта меню не заменяет проверку прав в действиях и API.

## Быстрый запуск

**Необходимо:** Node.js **22.18+** (ветка 22), **24** или **26** и npm. Основная разработка проверялась на Node.js **26.13.0**.

### Windows / PowerShell

```powershell
# Для приватного репозитория потребуется доступ к GitHub
git clone https://github.com/dimomm333/student-cabinet.git
cd student-cabinet

# Только при первом запуске. Не перезаписывайте существующий .env
Copy-Item .env.example .env

npm.cmd ci
npm.cmd run auth:setup
npm.cmd run db:setup
npm.cmd run dev
```

> В PowerShell, если выполнение `npm.ps1` запрещено политикой системы, используйте `npm.cmd` — как в примере выше.

### Linux / macOS

```bash
git clone https://github.com/dimomm333/student-cabinet.git
cd student-cabinet

cp .env.example .env   # только если .env ещё не существует
npm ci
npm run auth:setup
npm run db:setup
npm run dev
```

После запуска откройте:

- **Главная:** <http://localhost:3000>
- **Вход:** <http://localhost:3000/login>
- **Публичное расписание:** <http://localhost:3000/schedule>

`auth:setup` заполняет отсутствующие локальные настройки и создаёт случайный секрет, не заменяя существующие значения. Для VS Code также предусмотрена задача `Student cabinet: dev`.

Переменные первоначальных паролей: `DEMO_ALEXANDER_PASSWORD`, `DEMO_MARIA_PASSWORD`, `DEMO_TEACHER_PASSWORD`, `DEMO_DEANERY_PASSWORD`, `DEMO_STAFF_PASSWORD`, `DEMO_ADMIN_PASSWORD`.

- Пароли задаются **до первого seed** через переменные окружения либо генерируются автоматически.
- Автоматически созданные пароли сохраняются в локальном игнорируемом файле `.env.demo.local`.
- Существующие хеши паролей повторным seed **не заменяются**.
- Некоторые дополнительные преподаватели могут присутствовать в расписании **без учётных данных для входа**.
- Отдельный локальный сценарий физкультуры создаёт дополнительные синтетические аккаунты; его нельзя использовать для наполнения production-базы без специальной адаптации.

> [!IMPORTANT]
> Не публикуйте `.env`, `.env.demo.local`, файлы `credentials.json`, дампы SQLite, пароли или ключи. Даже приватный репозиторий не предназначен для хранения секретов.

## Конфигурация

Пример: [`.env.example`](./.env.example).

| Переменная | Назначение |
|:--|:--|
| `DATABASE_URL` | Путь к SQLite, локально обычно `file:./prisma/dev.db`. |
| `BETTER_AUTH_URL` | Точный адрес приложения. Для внешнего доступа используйте **HTTPS**. |
| `BETTER_AUTH_SECRET` | Секрет авторизации, минимум 32 символа; для сервера — отдельное значение. |
| `AUTH_TRUST_PROXY` | Доверие к заголовкам проверенного обратного прокси; по умолчанию `false`. |
| `AUTH_PROXY_SECRET` | Отдельный секрет между приложением и доверенным прокси, если эта схема включена. |
| `DEMO_*_PASSWORD` | Необязательные переменные начальных паролей демонстрационных аккаунтов. |

**Важные правила:**

1. Не создавайте второй `DATABASE_URL` в `.env.local`: приложение и Prisma должны использовать **один и тот же файл базы**.
2. Не меняйте `BETTER_AUTH_SECRET` на действующем сервере без плана перевыпуска сессий.
3. Проверяйте `BETTER_AUTH_URL` и настройки прокси при развёртывании: адрес и схема должны соответствовать публичному HTTPS origin.

Подробнее: [настройка авторизации и обратного прокси](./docs/auth-security-fixes.md).

## База данных и миграции

Модель: [`prisma/schema.prisma`](./prisma/schema.prisma). История изменений — в `prisma/migrations`.

### Существующая база

Перед миграцией **создайте согласованную резервную копию SQLite** (SQLite Backup API / `VACUUM INTO`, либо копия при остановленном приложении).

```bash
npm run db:generate
npm run db:deploy
npm run db:status
```

**Не используйте** `prisma db push` или сброс базы вместо штатных миграций. Не редактируйте SQL уже применённых миграций.

### Демонстрационные данные

```bash
npm run db:seed         # базовые аккаунты, профили и часть учебных данных
npm run db:useful       # каталог «Полезное»
```

`db:seed` предназначен для инициализации демосреды: текущая реализация добавляет отсутствующие записи и не сбрасывает уже заданные пароли; при этом обновляет известные демонстрационные новости. **На рабочем сервере запускайте seed только после проверки его действий и резервного копирования.**

Другие модули имеют собственные миграции, тесты и демосценарии. Например, `demo:physical-education:local` специально ограничен **локальной** базой `prisma/dev.db` и не должен запускаться на сервере с рабочими пользователями.

Подробные инструкции: [БРС](./docs/brs-journal.md), [деканат](./docs/deanery.md), [расписание](./docs/schedule.md), [редактор расписания](./docs/schedule-editor.md), [обходной лист](./docs/clearance.md), [справочник](./docs/useful.md).

## REST API

Расписание можно читать без отдельного API-сервера. Публичные эндпоинты:

| Метод | Маршрут | Назначение |
|:--|:--|:--|
| `GET` | `/api/v1/schedule` | Занятия по группе, преподавателю, дате или учебной неделе. |
| `GET` | `/api/v1/groups` | Поиск и список учебных групп. |
| `GET` | `/api/v1/teachers` | Поиск публичных сведений о преподавателях. |

Примеры запросов, параметры, формат ответов и ограничения: **[документация API](./docs/schedule-api.md)**.

## Безопасность и ограничения

Реализованы серверные проверки ролей и доступа к данным, Better Auth с хешированием паролей, HttpOnly/SameSite cookies, защита чувствительных операций и ограничение попыток входа. Для сессий предусмотрен абсолютный восьмичасовой срок; при HTTPS cookie помечается `Secure`.

При этом необходимо учитывать рамки проекта:

- Это **конкурсный прототип**, а не официальная промышленная вузовская система.
- Самостоятельная регистрация и пользовательский интерфейс сброса пароля не предусмотрены.
- Часть справочников и учебных результатов заполняется **отдельными** демонстрационными сценариями.
- SQLite рассчитана на приложение с постоянным локальным диском и требует аккуратного резервного копирования.
- Доступность действия определяется ролью, назначением и состоянием записи; некоторые функции не видны пользователям без соответствующих полномочий.

> [!CAUTION]
> Перед публичным развёртыванием проверьте HTTPS, секреты окружения, права файлов, резервное копирование, политику демонстрационных данных и доступность административных маршрутов. Не размещайте реальные персональные данные в конкурсном экземпляре.
