# Авторизация четырёх ролей: отчёт

Обновление 21 ноября 2026: общая смена собственного пароля доступна во всех пяти профилях через штатный Better Auth. См. [настройки профиля и безопасность](./profile-settings.md). Ниже сохранён исторический отчёт первоначальной реализации; его упоминание отсутствующей смены пароля больше не актуально.

Актуальное расширение до пяти ролей: [кабинет DEANERY_STAFF и область доступа](./deanery.md). Нижеследующий отчёт описывает первоначальное внедрение четырёх ролей.

Этот документ описывает первоначальное внедрение. Актуальные исправления выявленных аудитом проблем и повторные проверки: [SEC-01, SEC-02, SEC-03, DEP-01](./auth-security-fixes.md).

Реализовано 12 ноября 2026 года. Сохранены Next.js 16.4.6, Prisma 7.10.1 и прежний файл SQLite. Авторизация — Better Auth 1.7.22 с Prisma adapter, credential-паролями scrypt и серверными сессиями. Выбор основан на стабильном выпуске, заявленной поддержке Next.js 16/Prisma 7 и успешной production-сборке с реальным SQLite adapter проекта.

## Результат

| Пользователь | `/dashboard` | `/teacher` | `/staff` | `/admin` |
| --- | --- | --- | --- | --- |
| Без сессии | → `/login` | → `/login` | → `/login` | → `/login` |
| STUDENT | Доступ | → `/dashboard` | → `/dashboard` | → `/dashboard` |
| TEACHER | → `/teacher` | Доступ | → `/teacher` | → `/teacher` |
| TECHNICAL_STAFF | → `/staff` | → `/staff` | Доступ | → `/staff` |
| ADMIN | → `/admin` | → `/admin` | → `/admin` | Доступ |

Те же правила работают на вложенных страницах и при RSC-запросах. Проверка выполняется на сервере в layout и самой странице. Актуальная роль берётся из базы на каждом запросе. Неавторизованному клиенту не передаётся приветствие или содержимое защищённого кабинета.

## Получение демонстрационных паролей

Логины и соответствующие им имена переменных приведены в [README](../README.md#учётные-записи). Пароли не включены в исходный код и документацию. В этой рабочей копии они случайно сгенерированы и находятся только в игнорируемом локальном `.env.demo.local`; откройте его своим редактором. При настройке через окружение используйте своё хранилище секретов. Секрет подписи сессий находится отдельно в локальном `.env`.

## Ограничения

Новые модули имеют только страницы основы с отметкой «В разработке». Студенческие расписание, статистика, уведомления и остальные прежние демонстрационные сведения остаются визуальными примерами. Административный CRUD, пользовательское изменение профиля/пароля, восстановление пароля, MFA и учебные таблицы ещё не реализованы. Существующие пользователи вне пяти демонстрационных аккаунтов сохраняются миграцией, но их credentials необходимо выдавать отдельно доверенной административной процедурой.

Сессии действуют до восьми часов, без автоматического продления. SQLite требует постоянного локального диска и одного согласованного окружения `DATABASE_URL`. Для внешнего адреса требуется HTTPS; доверенный reverse proxy должен корректно перезаписывать IP-заголовки для ограничения попыток входа. Публичный deployment не выполнялся.
