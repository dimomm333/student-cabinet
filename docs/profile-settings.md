# Компактные настройки профиля и смена пароля

21 ноября 2026. Next.js 16.4.6, Better Auth 1.7.22.

Во всех пяти кабинетах настройки уведомлений свёрнуты по умолчанию; сразу за ними расположена свёрнутая «Безопасность». Персональные карточки сохранены. Раскрытие локально для страницы: кнопка с `aria-expanded`/`aria-controls`, Enter/Space, недоступное для фокуса закрытое содержимое (`inert`), анимация высоты с учётом `prefers-reduced-motion`. Обе темы используют существующие переменные палитры.

## Реализация

- [profile-settings.tsx](../src/components/profile-settings.tsx) проверяет текущего пользователя и передаёт клиенту только наличие локального пароля. Хеши и аккаунты не передаются в интерфейс.
- [profile-settings-section.tsx](../src/components/profile-settings-section.tsx) — общая раскрывающаяся карточка.
- [notification-settings.tsx](../src/components/notification-settings.tsx) сохраняет прежний API, переключатели и категории доставки.
- [password-settings.tsx](../src/components/password-settings.tsx) — общая форма: текущий/новый/повтор, показ паролей, ошибки непосредственно под полем с `aria-invalid`/`aria-describedby`, блокировка повторной отправки и очистка после успеха. При ошибке значения сохраняются. Без локального пароля показывается объяснение вместо формы.
- [password-policy.ts](../src/lib/password-policy.ts) — единые границы 8–128 символов для Better Auth и подсказок формы. Общая политика применяется библиотекой при регистрации, смене, установке и сбросе пароля; публичная регистрация и дополнительные endpoints остаются закрытыми. Отдельные требования 12–128 символов в скриптах выдачи демонстрационных/служебных аккаунтов сохранены.
- [auth.ts](../src/lib/auth.ts) — штатный `changePassword`, серверный запрет одинакового пароля, обязательный `revokeOtherSessions: true`, проверка абсолютного срока сессии и отдельное правило Better Auth: 5 запросов за 60 секунд на доверенный IP с хранением в существующей таблице RateLimit. Остальные лимиты сохранены. Встроенный специальный лимит версии 1.7.22 был 3 запроса за 10 секунд; новое правило уменьшает число попыток за минуту.
- [route.ts](../src/app/api/auth/[...all]/route.ts) разрешает только штатный POST `/api/auth/change-password` в дополнение к прежним маршрутам. Сохраняются точный Origin, trusted proxy, CSRF Better Auth и `private, no-store`. Другие auth endpoints остаются закрытыми.

Владелец определяется библиотекой по авторитетной серверной сессии; пользовательский `userId` не выбирает аккаунт. Текущий пароль проверяет и новый хеш создаёт Better Auth внутри штатного механизма с Prisma-транзакцией. Повтор пароля проверяется формой и не отправляется серверу. Пароли не записываются в настройки, браузерные хранилища или журналы приложения.

При отзыве остальных сессий эта версия Better Auth удаляет все старые сессии и создаёт новую cookie текущему браузеру. Database hook сохраняет исходные `createdAt` и предельный `expiresAt`, поэтому операция не продлевает абсолютные восемь часов (SEC-02). Сессии других пользователей не затрагиваются. Миграций и изменений основной БД нет.

См. [официальную документацию Better Auth](https://www.better-auth.com/docs/authentication/email-password). Поведение сверено с установленными исходниками `api/routes/update-user.mjs`, `api/routes/session.mjs`, `api/rate-limiter/index.mjs` и `api/dispatch.mjs`.

## Локальная проверка слабых паролей

[password-strength.ts](../src/lib/password-strength.ts) использует zxcvbn-ts: core 4.3.0, language-common 4.2.0, language-en 4.1.2. Точные версии и транзитивные зависимости закреплены в lock-файле. Общий словарь распространённых паролей, английские словари, графы клавиатур, повторы, последовательности, замены букв и Levenshtein оценивают предсказуемость; это не небольшой ручной denylist. Конфигурация следует [рекомендациям библиотеки](https://zxcvbn-ts.github.io/zxcvbn/guide/getting-started/) и [best practices](https://github.com/zxcvbn-ts/zxcvbn/blob/master/docs/guide/best-practices/README.md).

Принимается оценка не менее 10^8 попыток подбора. Используется число `guesses`, поскольку условие `score >= 3` из-за внутреннего запаса в пять попыток отклоняет даже случайные строки ровно из 8 символов. Диапазон остаётся 8–128; границы проверяются до оценки сложности. Никаких обязательных классов символов: длинные непредсказуемые фразы, в том числе из строчных букв, принимаются. Оценка локальная, без Pwned Password Matcher, сетевых запросов, аналитики или сохранения паролей. Словари лениво загружаются клиентом при использовании формы. Локальная оценка не является полной базой всех утечек и не гарантирует обнаружение любого известного пароля.

Общий `hooks.before` Better Auth применяет правило к `password` при `/sign-up/email` и `newPassword` при `/change-password`, `/reset-password` и серверном `setPassword`. У `setPassword` в установленной версии нет URL; в hook middleware better-call нормализует путь в `/`. `auth.api` запускает общий dispatch с хуками. Это проверяется вызовами настоящего API установленной версии, а не имитацией хука. Хеширование остаётся штатным Better Auth. Проверка входа и его фиктивное хеширование для неизвестного пользователя не получают новую политику, поэтому уже сохранённый слабый пароль по-прежнему подходит для входа. Обычный HTTP allowlist не расширялся: регистрация, установка и сброс остаются закрытыми снаружи.

Клиент использует ту же функцию оценки для ранней обратной связи, сервер повторяет её независимо. Сообщения из библиотеки не выводятся: коды переводятся через [password-policy.ts](../src/lib/password-policy.ts). Короткий, длинный, простой и прежний новый пароль отмечают поле «Новый пароль»; несовпадение — повтор; неверный текущий — текущий пароль. Ограничение длины текущего поля также проверяется отдельно. Форма не обрезает вставленный слишком длинный новый пароль молча: показывает ограничение 128 символов.

## Регрессия

[profile-settings-checks.mjs](../scripts/profile-settings-checks.mjs) встроен в [verify-cabinet-navigation.mjs](../scripts/verify-cabinet-navigation.mjs). Он использует только новую мигрированную тестовую БД и временные пароли, проверяя для каждой роли:

- порядок, исходное состояние и клавиатурное раскрытие секций; сохранение обеих групп категорий и почтового переключателя;
- обе темы на 346, 360, 390 и 1366 px без горизонтального переполнения; снимки профиля студента;
- несовпадение, отказ паролю из 7 символов в форме и на сервере (`PASSWORD_TOO_SHORT`), успешную смену на пароль ровно из 8 символов и вход с ним, слишком длинный пароль, неверный текущий пароль, запрет прежнего значения и очистку формы;
- повторную отправку во время запроса, серверный rate limit и CSRF, отказ анонимному пользователю;
- новый/старый пароль при входе, отзыв остальных сессий, сохранение текущего входа и исходного срока;
- подмену владельца, аккаунт без локального пароля и отказ просроченной сессии.

Существующие проверки профиля продолжают проверять персональные карточки только для чтения; исключены только новые общие настройки. Тест уведомлений раскрывает секцию перед сохранением. Навигационные проверки также проверяют чужие кабинеты, актуальную роль, выход и отсутствие Blocking Route/Instant/ошибок браузера; сравнивают основную БД до и после.

Команды запускаются после сборки, генерация выполняется последовательно:

```sh
npm run typecheck
npm run lint
npm run build
npm run test:auth
npm run test:auth:password
npm run test:notifications
npm run test:auth:navigation
npm run test:auth:navigation -- --production
```
