# Главная студента

Обновлено 20 ноября 2026 года. Маршрут `/dashboard` — компактный рабочий стол: расписание, строка уведомлений, «Учёба и контроль», объявления. Большой баннер, лозунги, дублирование профиля и счётчики-пустышки удалены. Приветствие содержит имя и связанную учебную группу; дата находится только в расписании.

## Компоненты и источники

Серверная [страница](../src/app/dashboard/page.tsx) проверяет STUDENT через `requireRole`, получает [общую модель главной](../src/lib/student-home.ts) и передаёт сериализуемый результат [клиентскому компоненту](../src/components/student-home.tsx). Сохранены Suspense/loading и Cache Components: персональные данные и решения о доступе не помещаются в общий кеш. Оформление описано в [dashboard-home.css](../src/app/dashboard-home.css) и использует существующие [семантические токены тем](./themes.md).

| Содержимое | Авторитетный источник | Поведение |
| --- | --- | --- |
| Имя, группа | `User`, `StudentProfile`, связанные `StudyGroup` | Имя из `firstName`, при отсутствии — первая часть существующего имени аккаунта. Курс и форма обучения не дублируются. |
| Сегодня, время, неделя | `AcademicTerm.timeZone`, `firstNumeratorMonday`, общие `currentAcademicDate` и `weekParity` | Текущая дата вычисляется на сервере в часовом поясе действующего опубликованного календаря. Числитель/знаменатель рядом с сегодняшней датой относится именно к ней, даже если ближайшее занятие на следующей неделе. |
| Занятия | [Общий репозиторий расписания](../src/lib/schedule-repository.ts), `effectiveSchedule`, существующая область групп/подгрупп | Учитываются публикация, регулярные пары, замены, дополнительные занятия, переносы, отмены, аудитории и преподаватели. Параллельного справочника нет. |
| Непрочитанные | [NotificationsProvider](../src/components/notifications-provider.tsx) | Только ссылка со строкой о количестве. Запросы, таймер и синхронизация вкладок остаются у существующего провайдера; главная не запрашивает уведомления самостоятельно. |
| Последние результаты | Опубликованные `BrsPlan`, свои `BrsResult`, действующие `BrsFinal` | До трёх последних результатов в модели, до двух на экране. Исключены удалённые, будущие и чужие оценки. Официальный результат проверяется через общий `calculateStudent` / `officialState`. Приватные комментарии не передаются. |
| Ближайший контроль | События модулей БРС, `brsSchedule`, `plannedOn` / `deadline`, `BrsPlan.examOn` | Реальная дата занятия берётся из общего расписания с учётом переноса/отмены. Неназначенная дата не выводится из номера недели. Учитываются РК, работы, зачёт/экзамен и остальные существующие типы; уже оценённые работы и завершённые дисциплины пропускаются. |
| Объявления | [Общая область новостей студента](../src/lib/news-repository.ts) | До трёх опубликованных записей университета/своего подразделения, без `isDemo`, будущих и чужих публикаций; только заголовок и дата. В текущей схеме нет признака важности, поэтому порядок хронологический. |

Ближайшей считается ещё идущая либо будущая неотменённая пара. Если сегодня всё закончилось, нет занятий или все отменены, выбирается следующий день с занятиями до конца опубликованных учебных периодов. Прежнего ограничения в 14 дней нет. В компактном списке выбранного дня сохраняются все его занятия, включая прошедшие и отменённые, чтобы изменения не теряли контекст. При отсутствии будущих пар показывается короткое сообщение без придуманных данных.

Ссылки занятий открывают точную дату/неделю/период полного расписания. Результат открывает существующий диалог работы в БРС; экзамен — соответствующую дисциплину сессии; объявление — доступную публикацию; строка уведомлений — существующий раздел.

Модель обновляется раз в минуту на видимой главной и при возвращении фокуса/сети/видимости. Отдельных часов на основе локального часового пояса браузера нет: дата и ближайшая пара заново определяются сервером. Фоновая вкладка не запускает минутный опрос. При сетевой ошибке остаются последние полученные сведения с явным сообщением и кнопкой повтора. Обновление не сбрасывает подтверждённую более новую версию расположения блоков.

## Персонализация и защита

«Настроить главную» открывает доступный нативный диалог: чекбоксы, кнопки выше/ниже, сброс, отмена и сохранение. Все блоки, включая расписание, можно переставить; три дополнительных блока можно скрыть. Расписание обязательно, но первым остаётся только по умолчанию. Скрытые разделы остаются в основном меню. Сброс изменяет черновик и требует обычного сохранения. На десктопе блоки идут в сохранённом порядке по строкам общей сетки из двух колонок; ниже 1100 px — последовательно в одну колонку. [Доработка кратких карточек и свободного порядка](./dashboard-home.md).

Сохранение привязано к аккаунту в отдельной минимальной модели `UserPreferences` существующей [схемы Prisma](../prisma/schema.prisma). `dashboardLayoutJson` содержит только ID блоков, их порядок и список скрытых. Академические сведения, токены и сессии в JSON/`localStorage` не записываются. Настройки сохраняются после F5, выхода и повторного входа, доступны с другого устройства. Другой аккаунт получает собственную раскладку.

[Валидатор раскладки](../src/lib/dashboard-layout.ts) разрешает ровно четыре известных уникальных ID и запрещает скрытие расписания. Его позиция может быть любой; старые настройки совместимы. Повреждённые сохранённые настройки дают стандартный порядок. Числовая версия обеспечивает compare-and-swap; устаревшая вкладка получает 409 с понятным сообщением вместо перезаписи более нового выбора.

[API `/api/dashboard`](../src/app/api/dashboard/route.ts): GET читает модель; POST сохраняет только раскладку и её версию. [Серверный слой настроек](../src/lib/dashboard-settings.ts) проверяет реальную сессию, её абсолютный срок и актуальную роль, при записи повторяет проверку в транзакции. Владелец определяется исключительно сессией. Параметры URL, чужой `userId`, лишние поля, неверные ID, версии и форма JSON отклоняются. POST требует свой Origin, JSON и тело не более 2048 байт; чтение тела ограничено по времени. Ответы `private, no-store`, `Vary: Cookie`. Для четырёх остальных ролей API закрыт, включая деканат с назначениями и без них. Защита входа/выхода не изменена.

## Безопасное обновление базы

[Миграция](../prisma/migrations/20261120010000_dashboard_preferences/migration.sql) только добавляет `UserPreferences` со ссылкой на `User`; существующие таблицы и строки не переписываются. Общие настройки уведомлений имеют другую семантику и не используются для хранения раскладки.

Для существующей SQLite:

```bash
npm run db:generate
npm run db:dashboard
```

[Скрипт подготовки](../scripts/prepare-dashboard.mjs) делает согласованную копию через SQLite `VACUUM INTO`, применяет миграции на отдельной пробной копии, проверяет сохранение всех прежних полей/строк, целостность, внешние ключи и повторное применение. Перед применением к исходной БД проверяет отсутствие изменений после резервирования, затем повторяет проверки сохранности. При активных писателях следует остановить приложение перед обновлением; сброс БД, изменение паролей и seed академических данных не выполняются. PostgreSQL в этом скрипте резервирования пока не поддерживается; сама модель использует переносимый Prisma API.

Локально миграция применена с успешной проверкой: `.local/dashboard-migration-49tifw/results.json`; согласованная резервная копия — `.local/dashboard-migration-49tifw/before.db`, пробная — `trial.db`. Старые пользователи, сессии, оценки и расписание сохранены. Эти файлы, как и вся `.local`, исключены из Git; резервные копии содержат приватные данные и не предназначены для публикации.

## Проверки

[Целевая регрессия](../scripts/verify-dashboard.mjs):

```bash
npm run test:dashboard -- --development
npm run test:dashboard
```

Каждый запуск создаёт новую мигрированную тестовую БД и случайные временные пароли, запускает отдельный сервер и проверяет неизменность рабочей БД по полному отпечатку. Фиксированные даты и примеры публикаций существуют только внутри тестовых фикстур. HTTP и персонализация проверяются на настоящем сервере; для визуальных временных сценариев браузер получает реальные DTO из этой же изолированной БД через подмену GET. Тестовых параметров времени/пользователя в рабочем API нет.

Покрыты занятия сегодня/сейчас, пустой день, завершение дня, полная/частичная отмена, перенос и аудитория, группы/подгруппы, отсутствие связи с группой, конец расписания, обе чётности, полночь/смена недели и другой часовой пояс. Проверены пустая БРС, свежая оценка, РК/экзамен, чужие/будущие/неопубликованные данные, область объявлений, 0/4 непрочитанных через существующий провайдер, все действия настройки, конфликт версий, F5, повторный вход, изоляция аккаунтов, ограничения API и реальные переходы в разделы. Ускоренные браузерные часы проверяют минутное обновление академического дня.

В обеих темах сохранены полноразмерные снимки 346, 360, 768, 1366 px и снимки диалога 346/360 px; для временных сценариев — отдельные снимки 360 px. Вычисленные цвета маркеров проверяются на сохранение зелёного характера; горизонтальное переполнение и центрирование диалога проверяются автоматически. Снимки дополнительно просмотрены визуально, в том числе после исправления центрирования диалога. Редкие прочие разделы этим редизайном не менялись; регрессии навигации охватывают все пять кабинетов.

Фактически прошли `typecheck`, `lint`, production `build`, `test` (расписание), `test:schedule:browser`, `test:brs`, `test:notifications`, `test:auth`, `test:auth:navigation` в dev и production, `test:header`, целевой `test:dashboard` в dev и production. Отдельный полный `test:themes` в рамках редизайна не запускался: обе темы новой главной проверены целевой регрессией. Проверок Linux VPS и физического телефона не было; браузерные размеры эмулированы Chrome/Playwright на Windows.
