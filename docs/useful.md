# Справочник «Полезное»

Студенты открывают каталог из меню кабинета или по адресу `/dashboard/useful`. Главная показывает пять категорий. Поиск по названию и описанию охватывает всю опубликованную ветку, включая вложенные записи. Фильтр ограничивает поиск выбранной категорией. Прямые ссылки на карточки сохраняются при переносе, а хлебные крошки показывают текущее положение.

## Начальное содержимое

- В каталоге 35 основных материалов, 5 категорий и 19 вложенных записей.
- Страница `/dashboard/mail` берёт ссылку из опубликованного внешнего ресурса `university-mail`. Администратор задаёт её в `/admin/useful/university-mail`. Пустой URL оставляет страницу в состоянии «Почтовый сервис пока не подключён».
- «Структура университета» содержит ветки институтов и кафедр, контактов деканатов и справочника сотрудников. Публикация учебного подразделения требует явного решения администратора. Карточку можно связать с `AcademicDepartment`, чтобы название читалось из учебных данных. Эта модель также содержит учебные отделы, поэтому автоматического импорта кафедр нет.
- В каталогах клубов и спортивных секций есть нейтральные категории. Действующие организации, секции, конкурсы, адреса, телефоны, имена сотрудников и официальные URL не опубликованы без подтверждённых сведений. `Building` хранит названия корпусов и сведения для расписания, но не адреса. Для карты используется один подключаемый официальный ресурс.
- Инструкции ведут в «Услуги», «Моё расписание», «Сессию», «Успеваемость», «Общежитие» и «Портфолио» там, где у этих разделов уже есть соответствующие функции. Услуги используют действующий механизм доступности и обработки заявлений.
- «Физкультура» пока не имеет отдельного реестра секций. Если появится такой модуль, опубликованные карточки справочника могут быть источником либо содержать ссылки на карточки нового модуля. В этом случае следует выбрать один источник описаний, контактов и мест.

## Управление

1. В кабинете администратора откройте «Полезное» → «Добавить запись» или найдите существующую карточку. У справочника также есть кнопка «Добавить вложенную запись».
2. Выберите тип и родительский раздел. Верхний уровень предназначен для категорий. Для схемы «университет → институты → институт → кафедра» создавайте справочники с соответствующими родителями. Меньшее число в поле «Порядок» поднимает запись среди соседей.
3. Добавьте краткое описание и текст. Редактор принимает абзацы, заголовки, нумерованные и маркированные списки, **выделение** и ссылки. Ссылки на карточки используют пути вида `/dashboard/useful/идентификатор` с идентификатором из адреса редактора. HTML отображается как текст. Для внешнего адреса допускаются только полные HTTP/HTTPS URL.
4. Для карточки добавьте согласованные публичные контакты и место, если они известны. Для проверенного учебного подразделения можно выбрать запись из учебных данных. Справочник сотрудников наполняется вручную согласованными публичными сведениями.
5. Выберите «Опубликована», чтобы показать запись студентам. Черновики и архив скрыты. Скрытая родительская запись закрывает всю ветку, включая прямые ссылки и поиск. При архивировании ветки интерфейс просит подтвердить действие. Дочерние записи сохраняют собственный статус. Возврат ветки в публикацию снова открывает опубликованных потомков.

Студенческие страницы и серверное действие проверяют роль при каждом запросе. Редактирование доступно только `ADMIN`. Дерево защищено от циклов транзакционной проверкой. Внешние ссылки проверяются при записи и использовании. Карточка ресурса без URL ведёт на общую страницу с сообщением, а карточка с URL — на официальный сайт.

Для GET и HEAD на двух ветках справочника ранняя проверка в `src/proxy.ts` отправляет перенаправление для гостей и других ролей до рендера layout. Это устраняет предупреждение Instant при отказе в доступе. Proxy, layout, страницы и серверное действие используют общую проверку сессии и актуальной роли. Границы загрузки и диагностика Next.js остаются включёнными.

## Локальная SQLite

После установки зависимостей выполните `npm run db:generate`. Существующую локальную базу из `DATABASE_URL` подготовьте командой `npm run db:useful`. На время операции остановите запись в базу. Команда создаёт согласованный снимок через `VACUUM INTO` в игнорируемой папке `.local/useful-migration-*/before.db`, проверяет миграцию `20261122150000_useful_catalog` и заполнение на отдельной копии, затем применяет их к исходной SQLite. Она сверяет данные вне каталога, проверяет целостность и выводит путь к резервной копии. Для прогона только на копии выполните `node --env-file-if-exists=.env scripts/prepare-useful.mjs`.

Начальное заполнение также входит в обычную команду `db:seed` для новой базы. Повторный запуск добавляет только отсутствующие исходные идентификаторы и сохраняет правки, порядок и статусы администратора. SQLite-специфичны SQL миграции и создание снимка. Чтение, редактирование и заполнение используют Prisma Client.

Регрессия на отдельной базе запускается командой `npm run test:useful`. После production build можно добавить `-- --production`.
