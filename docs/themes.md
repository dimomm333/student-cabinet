# Светлая и тёмная темы ЛКС

Реализация и проверка: 19 ноября 2026 года. Next.js 16.4.6, React 19.3.0.

## Переключение и сохранение

Общая кнопка [ThemeToggle](../src/components/theme-toggle.tsx) находится слева от колокольчика в обеих оболочках кабинетов, в публичной шапке и рядом с логотипом на странице входа. В светлой теме отображается луна, в тёмной — солнце. Доступное имя, `title` и подсказка называют тему, на которую переключит кнопка: только «Светлая» или «Тёмная». Работают Tab, Enter и Space, предусмотрен видимый focus.

Выбор хранится в `localStorage["lks-theme"]`: `light` или `dark`. Настройка относится к браузеру и сайту, сохраняется после обновления, выхода и входа другой учётной записью. Она не связана с БД или пользовательской сессией.

При отсутствии корректного сохранённого значения используется `matchMedia("(prefers-color-scheme: dark)")`. Пока ручного выбора нет, изменения системной темы применяются сразу. Ручной выбор имеет приоритет; системные изменения больше его не переопределяют. Событие `storage` синхронизирует вкладки; удаление ключа возвращает следование системе. Отдельного режима «Автоматически» в интерфейсе нет.

Недоступный `localStorage` не ломает приложение: системная тема и ручное переключение работают в памяти текущей страницы. Сохранить выбор между полными загрузками в таком браузере невозможно.

## SSR, первый кадр и Cache Components

В [корневом layout](../src/app/layout.tsx) статический синхронный скрипт из [theme.ts](../src/lib/theme.ts) расположен в `<head>`. Он читает сохранённый выбор и устанавливает `data-theme` на `<html>` во время разбора HTML, до первого отображения содержимого. Тема не определяется после первого paint через `useEffect`.

Подход соответствует руководству установленного Next.js: `node_modules/next/dist/docs/01-app/02-guides/preventing-flash-before-hydration.md`, раздел Themes.

`suppressHydrationWarning` применяется только к `<html>`, поскольку его атрибут намеренно меняет ранний скрипт. Серверная разметка кнопки стабильна; `useSyncExternalStore` синхронизирует доступное имя после гидратации. CSS выбирает нужную иконку уже в первом кадре. `ThemeController` в `useLayoutEffect` повторно применяет настройку при dev-remount React и подписывается на системные изменения и события хранилища.

Сессии и права не читаются механизмом темы. Cache Components, Partial Prefetching, серверные проверки доступа и существующие границы Suspense/loading сохранены. Бизнес-логика, Prisma-схема, основная БД, назначения и авторизация не изменены; миграций нет.

При будущем введении строгой CSP раннему inline-скрипту потребуется разрешённый nonce или hash в рамках общей политики сайта.

## Цветовые переменные

Общие токены находятся в [themes.css](../src/app/themes.css). Существующие [globals.css](../src/app/globals.css), [services.css](../src/app/services.css) и [materials.css](../src/app/materials.css) используют их в тех же правилах компонентов, без копирования CSS для второй темы.

Светлая тема сохраняет прежние локальные оттенки через fallback: например, `var(--surface-soft, #edf1e8)`. В тёмной теме этот же семантический токен имеет единое значение. Это позволяет сохранить исходную светлую палитру, включая небольшие различия между разделами. Новому компоненту следует использовать существующие токены и указать нужный светлый fallback для варианта, если у токена нет общего светлого значения.

| Назначение | Переменные | Значение в тёмной теме |
| --- | --- | --- |
| Основной фон | `--background`, `--page-surface` | `#000000` |
| Боковое меню и верхняя панель | `--chrome` | `#000000` |
| Карточки, поля, диалоги | `--surface`, `--surface-paper` | `#080808`; paper сохраняет исходные почти белые оттенки светлой темы |
| Дополнительные поверхности | `--surface-raised`, `--surface-soft` | `#0c0c0c`, `#121212` |
| Наведение и выбор | `--surface-hover`, `--surface-active` | `#1c1c1c`, `#15271c` |
| Основной текст | `--foreground`, `--text-primary` | `#ededed` |
| Второстепенный текст | `--muted`, `--text-secondary` | `#ababab` |
| Зелёные ссылки и заголовки | `--green`, `--green-dark` | `#83d5a4`, `#a3e8bf` |
| Зелёные кнопки | `--action-bg`, `--action-hover`, `--on-action` | Тёмно-зелёный фон, светлый текст |
| Разделители и границы | `--line`, `--border-subtle`, `--border-strong` | `#292929`, `#333333`, `#626262` |
| Focus | `--focus` | `#83d5a4` |
| Успех | `--success-surface`, `--success-text`, `--success-border` | Тёмная поверхность, светло-зелёный текст |
| Предупреждение | `--warning-surface`, `--warning-text`, `--warning-border` | Тёмная поверхность, сдержанный золотистый текст |
| Ошибка | `--danger-surface`, `--danger-text`, `--danger-border` | Тёмная поверхность, светло-красный текст |
| Счётчик колокольчика | `--danger-solid` | Красный `#b42332` |
| БРС | `--table-border`, `--table-grid`, `--table-head`, `--table-row`, `--table-column`, `--table-active` | Отдельные различимые состояния сетки и перекрёстной подсветки |
| Подсказки | `--tooltip-bg`, `--tooltip-text` | `#202020`, `#ededed` |
| Прозрачные декорации и тени | `--surface-overlay`, `--border-overlay`, `--shadow` | Сдержанные прозрачные значения |

`color-scheme` согласует нативные select, календарь даты, checkbox и браузерные диалоги с выбранной темой. Учтены placeholder, autofill и кнопки выбора файла. Существующие disabled-состояния сохранены. Фото, логотип, документы, QR-коды и другие медиа не инвертируются и не фильтруются. Светлые участки внутри исходного изображения документа или фотографии являются частью самого изображения.

Размеры и компоновка контента сохранены. На узком экране публичная навигация переносится на отдельную строку, а необязательная отметка «Деморежим» скрывается в шапке кабинета, чтобы переключатель, колокольчик и профиль помещались вместе. Стили положения счётчика колокольчика не менялись.

## Проверка в браузере

Проверки выполнялись в настоящем Chrome через Playwright, с изолированной мигрированной тестовой БД, вымышленными данными и случайным временным паролем. Все операции записи тестов относятся только к этой БД; полный fingerprint основной БД сравнивается до и после.

Для обеих тем проверена матрица ширин **346, 360, 768 и 1366 px**, все пункты меню пяти кабинетов и публичные страницы. Снимки тёмной темы сохранены локально. Проверяются основной чёрный фон и шапка, отсутствие светлых UI-поверхностей, горизонтального переполнения, пересечения кнопок, фильтров на медиа, ошибки браузера и диагностика Next.js. Для непрозрачных текстовых поверхностей тёмной темы дополнительно рассчитывается контраст WCAG AA; эта проверка дополняет визуальный просмотр и не заменяет полный аудит доступности.

Вручную просмотрены скриншоты следующих страниц и состояний:

- Публичные главная, расписание и вход, ошибка входа; светлая главная и светлый вход для сравнения.
- Студент: главная, профиль с фотографией и настройками уведомлений, расписание и открытый календарь, успеваемость с большой таблицей БРС, диалог результата, сессия, каталог материалов, новости, уведомления с прочитанными и непрочитанными строками, заявление с документами и историей, подтверждение удаления черновика, мобильное меню и состояние загрузки материалов.
- Преподаватель: главная, расписание, большой журнал и посещаемость, форма загрузки материалов на desktop и телефоне.
- Деканат: главная, студенты и группы, расписание и открытый диалог редактора на desktop и телефоне, очередь заявлений, успеваемость, планы БРС, допуски, сессия.
- Администратор: главная, форма объявления, очередь заявлений, существующая страница пользователей.
- Техперсонал: главная, очередь заявлений и существующая страница оборудования.

Проверены переключение без перезагрузки, Enter/Space, F5, выход и следующий вход всех пяти ролей, системные изменения до ручного выбора, приоритет ручного выбора, другая вкладка и отказ хранилища. Первый отрисованный кадр проверяется с сохранённой тёмной темой, светлой системной настройкой и искусственно задержанным JavaScript React.

Скриншоты снимаются с `caret: 'initial'`: стандартное скрытие каретки Playwright временно добавляет inline-стили полям и могло само вызвать диагностическое сообщение при гидратации потоковой dev-страницы. Стили приложения ради устранения этого эффекта тестового инструмента не изменялись.

```sh
npm run typecheck
npm run lint
npm run build
npm run test:themes
npm run test:themes -- --development
npm run test:auth
npm run test:auth:navigation
npm run test:auth:navigation -- --production
npm run test:brs
npm run test:materials
npm run test:services:ui
npm run test:schedule:browser
```

- TypeScript, ESLint и production build — успешно.
- Финальная дополнительная проверка исходного почти белого поля входа (`#fcfdfb`) и переключения туда/обратно — успешно; в тёмной теме поле `#080808`, фон `#000000`, ошибок браузера нет.
- Безопасность — успешно: пять ролей, CSRF, SEC-01/02/03, proxy/cookie и неизменность исходных данных.
- Навигация пяти ролей в dev и production — успешно: 47 разделов меню с возвратом на главную, профили и чужие параметры, смена роли, чужие кабинеты, выход; ошибок браузера и предупреждений Blocking Route/Instant нет.
- Регрессии БРС — успешно: расчёты, роли и назначения, редактирование, диалоги, таблицы, мобильные режимы, приватность и сохранность данных.
- Материалы — успешно: доступы пяти ролей, папки, публикации, загрузка и скачивание, поиск, сетевые ошибки, полный responsive CRUD на четырёх заданных ширинах.
- Услуги — успешно: 16 форм, документы, автосохранение, история, восстановление после сетевых ошибок, подтверждения удаления, выход и следующий вход, 360/1366 px.
