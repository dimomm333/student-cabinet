# Консультации

- **Студент** открывает «Учёба» → «Консультации» (`/dashboard/consultations`). Видны консультации, назначенные его текущей учебной группе. Начальный список показывает ближайшие встречи в хронологическом порядке. Поиск принимает ФИО и название дисциплины. Фильтры по преподавателю, дисциплине и дате можно сочетать. Для просмотра истории выберите «Прошедшие».
- **Преподаватель** открывает «Консультации» (`/teacher/consultations`) и просматривает собственное расписание во вкладках «Ближайшие» и «Прошедшие». Для переноса или отмены обратитесь в деканат.
- **Деканат** открывает «Консультации» (`/deanery/consultations`), раскрывает «Новая консультация», заполняет поля и нажимает «Добавить консультацию». На карточке можно изменить расписание или подтвердить отмену. Для отменённой консультации сохраняется отметка, а интервал освобождается. Раздел предназначен для просмотра расписания и работы деканата. Участники приходят в указанную аудиторию.

Сотрудник деканата видит и изменяет консультацию, если все её группы входят в подразделения, на которые у него есть действующие назначения. При сохранении у каждой целевой группы проверяется сочетание преподавателя и дисциплины через активное учебное назначение или опубликованное расписание пар. Консультации можно проводить и между учебными периодами. Консультация может быть назначена нескольким группам. Доступ студента определяется точной привязкой к одной из этих групп. Если нужны отдельные подгруппы, сотрудник выбирает их явно.

Время московское. Интервал задаётся началом и окончанием в пределах даты. Преподаватель и аудитория проверяются по другим действующим консультациям и фактическим занятиям, включая разовые замены и переносы. Соседние интервалы с общим временем окончания и начала допустимы. Пары, изменённые в редакторе расписания уже после создания консультации, могут потребовать переноса консультации.

## Обновление на Linux VPS

Миграция `20261122180000_consultations` добавляет таблицы `Consultation` и `ConsultationGroup` с внешними ключами к существующим справочникам. Учебное расписание, оценки и учётные записи сохраняются. Для ввода раздела в работу достаточно миграции без наполнения демонстрационными данными.

1. В каталоге новой версии установите зависимости из lock-файла и соберите приложение на Linux с рабочими настройками окружения. Убедитесь, что `DATABASE_URL` указывает на существующий файл базы с постоянным хранением.

   ```bash
   npm ci
   npm run build
   ```

2. Остановите приложение и другие процессы записи штатным менеджером служб. Сделайте согласованную резервную копию вне репозитория. Подставьте актуальный путь к файлу SQLite и новый путь резервной копии с ограниченным доступом.

   ```bash
   db=/путь/к/рабочей.sqlite
   backup=/закрытый/каталог/student-cabinet-before-consultations.sqlite
   test -f "$db" && test ! -e "$backup" &&
     (umask 077 && sqlite3 "$db" ".backup '$backup'")
   sqlite3 -readonly "$backup" 'PRAGMA integrity_check;'
   ```

3. Проверьте миграцию на отдельной копии бэкапа с временным `DATABASE_URL`. Сравните данные прежних таблиц до и после миграции и проверьте целостность.

   ```bash
   trial=/закрытый/каталог/student-cabinet-migration-test.sqlite
   test ! -e "$trial" && cp -- "$backup" "$trial" &&
     DATABASE_URL="file:$trial" npm run db:deploy
   sqlite3 -readonly "$trial" 'PRAGMA integrity_check; PRAGMA foreign_key_check;'
   ```

   После успешной проверки в окружении рабочей службы примените миграции и проверьте статус. Проверка `integrity_check` должна вернуть `ok`, а `foreign_key_check` — пустой результат.

   ```bash
   npm run db:deploy
   npm run db:status
   sqlite3 -readonly "$db" 'PRAGMA integrity_check; PRAGMA foreign_key_check;'
   ```

4. Запустите новую версию через менеджер служб и проверьте открытие раздела под соответствующими ролями. При сбое миграции держите процессы записи остановленными, пока не проверите состояние базы и резервной копии.

Для браузерного теста на отдельной SQLite используйте `npm run test:consultations` после `npm run build`. Скрипт поднимает собственный сервер и проверяет создание, доступ участников, фильтры, занятость, изменение, отзыв полномочий, отмену и сохранение после перезапуска.
