# Учебные материалы

Рабочие разделы: `/dashboard/materials` и `/teacher/materials`. Общий интерфейс и серверный слой используются обоими кабинетами. Фиктивные дисциплины и демонстрационные файлы не добавляются.

## Модели и реальные учебные связи

[Схема](../prisma/schema.prisma) связывает `LearningMaterial` с существующими `Discipline`, `AcademicTerm`, автором `User` и через `MaterialTarget` с `StudyGroup`. Новый справочник дисциплин, преподавателей или групп не создаётся. `TeachingAssignment` определяет полномочия преподавателя; опубликованные планы БРС также дают студенту список дисциплин, в том числе без материалов. Год вычисляется из начала реального семестра (август–июль); семестры выбираются явно. Текущий семестр показывается первым, остальные доступны в списке.

- `MaterialFile` — физический файл: случайный ключ, исходное имя, размер, определённый по содержимому MIME, SHA-256. Один материал имеет один файл либо одну внешнюю HTTP/HTTPS-ссылку. Для нескольких групп создаются связи доступа к одному материалу и файлу.

Заголовок файла — только название преподавателя, без автоматического добавления исходного имени. При пустом названии используется имя без последнего расширения; правило одинаково при загрузке и редактировании, а поиск использует сохранённый заголовок. Оригинальное имя остаётся отдельными метаданными и передаётся при скачивании. Тире и иной авторский текст сохраняются. Ранее сохранённые названия не переписываются и не обрезаются по предполагаемому суффиксу: для старых записей нет признака, позволяющего надёжно отличить автоматическую склейку от авторского текста; их можно исправить обычным редактором.

Проверка исправления названий: `typecheck`, `lint`, production build и [серверный/браузерный тест материалов](../.local/materials-test-JSH3jq/results.json) прошли. Проверены пустое и заданное название, массовая загрузка, авторское тире (включая точное совпадение суффикса с именем файла), карточки обоих кабинетов, поиск, редактор и оригинальное имя при скачивании. Основная БД не изменялась.
- `LearningMaterial` — название, описание, дисциплина, семестр, категория, папка, автор, статус DRAFT/PUBLISHED, версия, время создания/изменения, первой публикации и логического удаления. `searchTitle` обеспечивает поиск без учёта регистра, включая кириллицу.
- `MaterialFolder` — дерево внутри категории, автора, дисциплины и семестра; версия для конкурентных изменений. Категории: лекции, практики, лабораторные, прочее. Материалы могут лежать прямо в категории.
- `MaterialPublication` и `MaterialPublicationItem` — состав пакетной первой публикации для проверки актуального доступа в общей системе уведомлений.
- `MaterialReceipt` — ключ команды, хеш её содержимого и результат. Один ключ с другим содержимым отклоняется. Повтор загрузки сравнивает также хеш, имя, MIME и размер файла; новый временный файл удаляется после возврата первоначального результата.
- `MaterialAudit` — автор, действие, объект, время; содержимое документов и описаний в журнал не копируется. `MaterialWriteState` сериализует изменяющие транзакции SQLite.

## Права

[materials-permissions.ts](../src/lib/materials-permissions.ts) проверяет актуальные сессию, абсолютный срок её действия и роль из БД. Это выполняется около чтения и внутри транзакции изменения. После приёма файла проверка повторяется; истёкшая или отозванная сессия не может сохранить материал. Страницы дополнительно требуют соответствующую роль за Suspense/loading. Cache Components не отключён; решения о правах и сессии не кешируются между запросами.

Студент читает и скачивает только опубликованные, неудалённые материалы, назначенные его текущей группе либо её предкам. Студент подгруппы наследует материалы общей группы; назначение только соседней подгруппе доступа не даёт. Если в профиле указана только общая группа, материалы отдельных подгрупп не выдаются: требуется реальное назначение студента в подгруппу.

Преподаватель читает собственные материалы, включая черновики и архив. Создание и изменение требуют действующего `TeachingAssignment` на дисциплину и семестр. Назначение общей группе позволяет выбрать её подгруппы, назначение подгруппе не расширяется на родителя или соседей. Каждая целевая группа проверяется сервером. Изменять чужие материалы нельзя даже преподавателю с таким же назначением.

После отзыва назначения собственные материалы сохраняются для чтения автором. Если отозвано хотя бы одно назначение целевой группы, изменение такого материала полностью блокируется до восстановления полномочий. Ранее опубликованные материалы остаются доступными адресованным группам: отзыв преподавательского назначения сам по себе не удаляет уже выпущенные учебные ресурсы. Изменения папок требуют действующего назначения на дисциплину/семестр.

ADMIN, TECHNICAL_STAFF и DEANERY_STAFF не получают доступа к API материалов, включая скачивание. Административное делегирование управления материалами в этом выпуске не предусмотрено; назначение деканата на подразделение этого права не даёт. Для будущего управления администратором потребуется отдельное явное полномочие, интерфейс и тесты.

## Папки, публикация и архив

Создание, переименование и перемещение папок проверяют область назначения и категорию; циклы и глубина свыше 32 уровней запрещены. Удаление требует подтверждения и возможно только для пустой папки. Сервер не удаляет вложенное содержимое автоматически: сначала его нужно переместить. Материал переносится через редактор с выбором категории и папки.

Файлы и ссылки первоначально сохраняются как черновики. Публикация выбранных материалов выполняется одной транзакцией (до 100 записей), с проверкой версии каждого объекта. Снятие публикации немедленно закрывает последующие чтения и скачивания студентам. Удаление материала требует подтверждения и является логическим: сохраняются аудит и физический файл, ссылка на папку снимается. Автоматического физического удаления или удаления архива нет.

Прошедший семестр сохраняется без копирования в новый год. Просмотр студентом архива использует текущую принадлежность группе; после перевода в другую группу доступ к материалам прежней группы отзывается. Исторические персональные зачисления проект пока не хранит, поэтому произвольный доступ к прежней группе не восстанавливается по результатам БРС. Изменение архивных материалов требует действующего назначения на соответствующий старый семестр.

## Маршруты и API

[Общий API](../src/app/api/materials/route.ts):

- `GET /api/materials` — доступные дисциплины, семестры, преподаватели и количества опубликованных материалов.
- `GET /api/materials?termId=…&disciplineId=…` — материалы (по 50), видимые папки и полномочия; фильтры `q`, `category`, `folderId`, `page` (с нуля). `materialId` открывает конкретный доступный материал по глубокой ссылке.
- `GET /api/materials?file=ID_МАТЕРИАЛА` — проверка конкретного материала и потоковое скачивание.
- `POST /api/materials` — JSON-команда с `requestId`, `disciplineId`, `termId`; операции `CREATE_LINK`, `EDIT`, `DELETE`, `PUBLISH`, `UNPUBLISH`, `CREATE_FOLDER`, `EDIT_FOLDER`, `DELETE_FOLDER`. Изменение требует актуальной версии. `PUBLISH` принимает `items: [{id, version}]`. Удаление требует `confirmed: true`.
- `POST /api/materials?upload=1` — поток: 4 байта длины JSON (uint32 big-endian), UTF-8 JSON-команда `UPLOAD` до 32 КиБ, затем байты файла. `X-File-Name` содержит URL-кодированное имя. Общие параметры пакета передаются в ограниченном теле запроса, поэтому длинное кириллическое описание не переполняет HTTP-заголовки.

Все ответы API имеют `private, no-store`, `Vary: Cookie`, `nosniff`; запись требует точного Origin из `BETTER_AUTH_URL`, `cross-site` запрещён. JSON ограничен 32 КиБ и 15 секундами приёма. Файлы отдаются как attachment с безопасным ASCII-именем, UTF-8 filename*, CSP sandbox и длиной. Ссылки открываются с `noopener noreferrer`, сервер их не запрашивает.

[Интерфейс](../src/components/materials-workspace.tsx) поддерживает общий выбор групп/папки для пакета, предварительный список, реальный XHR upload progress и отдельную фазу проверки. При сетевом сбое повторяется оставшаяся часть с прежними ключами; успешные загрузки повторно не создаются. Незавершённые изменения защищены предупреждением при закрытии окна и переходах по ссылкам приложения. После перезагрузки окна браузер требует выбрать локальные файлы заново; долговременного восстановления локальных файлов нет.

## Приватное хранилище и проверка файлов

[Хранилище](../src/lib/materials-storage.ts) использует те же безопасные принципы, что и файлы услуг: приватный каталог вне `public`, UUID вместо пользовательского пути, эксклюзивное создание, права каталога 0700 и файла 0600 на Linux. Правила услуг и их PDF-валидатор не изменены: материалы имеют отдельный валидатор с более широким набором форматов.

```dotenv
MATERIALS_STORAGE_DIR=.local/material-files
MATERIALS_MAX_FILE_MB=32
```

Путь может задаваться окружением как отдельный приватный том. Лимит файла — 32 МиБ по умолчанию, настраивается от 1 до 128 МиБ. Бинарный запрос пишется на диск частями, без накопления полного тела в серверной памяти. Приём ограничен пятью минутами; одновременно в одном процессе допускаются две загрузки/проверки. Скачивание также потоковое. [Валидатор](../scripts/validate-material-file.mjs) читает ограниченный файл в отдельном процессе с ограничением heap 256 МиБ и 20 секунд.

Допустимы PDF; DOC/PPT/XLS (CFB с соответствующим потоком); DOCX/PPTX/XLSX (ZIP с соответствующей структурой Office и типами частей); TXT в UTF-8, UTF-16 с BOM или Windows-1251; JPEG/PNG; ZIP. Реальный тип вычисляется независимо от присланного Content-Type. Имена без путей, управляющих символов, двоеточий и `..`, до 240 символов. Изображения декодируются для проверки (до 40 млн пикселей). Документы не рендерятся и не выполняются на сервере.

ZIP проверяется по центральному каталогу и локальным заголовкам, CRC и фактической распакованной длине; запрещены опасные пути, symlink, дубли, исполняемые вложения, шифрование и вложенные архивы. До 2000 записей, до 64 МиБ на запись и 128 МиБ суммарно после распаковки, коэффициент до 200 для записей свыше 1 МиБ. ZIP64, многотомные архивы и методы кроме stored/deflate не принимаются. Распаковка выполняется только в ограниченный буфер проверки, на диск содержимое архива не извлекается. OOXML с VBA/ActiveX отклоняется.

PDF допускает обычные ссылки и object streams, проверяется парсером без исполнения действий; JavaScript, Launch, вложенные файлы, RichMedia, XFA и опасные URI отклоняются. До 2000 страниц и 80000 объектов с лимитами декодирования. Зашифрованные и повреждённые документы не принимаются. Это проверка формата и ограничений, а не антивирусная гарантия.

## Уведомления

Используются существующие `NotificationEvent`, `Notification`, настройки и email-outbox. При первой публикации пакета создаётся одно необязательное событие `source=MATERIALS`, `category=STUDY` («Учёба»); получатели вычисляются сервером по текущим группам и наследованию. Пакет ограничен одной дисциплиной и семестром. В событие не копируются имена файлов, описание или содержимое.

Черновики, просмотр, загрузка до публикации, идентичный повтор команды и повторная публикация ранее опубликованного материала уведомления не создают. Добавление новых целевых групп к уже публиковавшемуся материалу также не создаёт повторного уведомления. Общий scope ленты, счётчика, массового прочтения и email worker дополнительно проверяет наличие хотя бы одного доступного опубликованного материала в пакете. После удаления/снятия последнего материала или отзыва студенческого доступа событие скрывается, письма больше не отправляются. Уже начатое скачивание или принятый SMTP-сервером email отозвать нельзя.

## Миграция и эксплуатация

[Миграция](../prisma/migrations/20261118180000_materials/migration.sql) добавляет только новые таблицы и индексы. [Подготовка](../scripts/prepare-materials.mjs) делает согласованный SQLite `VACUUM INTO` в приватный игнорируемый каталог, проверяет integrity/FK, применяет миграции к второй копии, сравнивает все прежние поля и строки и проверяет повторный deploy. Перед `--apply` проверяет неизменность исходной БД. На production остановите запись приложения на время применения. `migrate reset` не используется.

```sh
node --env-file-if-exists=.env scripts/prepare-materials.mjs
npm run db:materials
npm run typecheck
npm run lint
npm run build
npm run test:materials
npm run test:notifications
npm run test:brs
npm run test:schedule:editor
npm test
npm run test:auth
npm run test:auth:navigation
npm run test:auth:navigation -- --production
```

Генерацию Prisma/Next и build выполнять последовательно. [Тест материалов](../scripts/verify-materials.mjs) создаёт новую БД, отдельное хранилище и временные пароли, запускает настоящий production-сервер и Chrome, сохраняет отчёт/снимки 360/1366 px в приватном `.local/materials-test-*`. Основная БД сравнивается до/после теста. Ключи, cookies, документы и backup в Git не добавляются.

Перед production необходимы Linux-проверка, HTTPS/reverse proxy с лимитами тела и таймаутом для медленных загрузок, приватный устойчивый том, согласованные резервные копии БД вместе с файлами, мониторинг свободного места и отдельная политика хранения/физической очистки удалённых и оставшихся после аварии файлов. Антивирусная инфраструктура не подключена. SQLite-специфичны DDL, согласованное копирование и сериализация записи; бизнес-логика использует Prisma, для PostgreSQL нужна отдельная миграция и проверка конкуренции. Windows node_modules и локальная БД на production вместо установки/миграции не копируются.
