# Компактное расписание и порядок блоков главной

Обновлено 20 ноября 2026 года. Основная архитектура, источники и первоначальная миграция описаны в [dashboard.md](./dashboard.md).

## Краткое расписание

[StudentHome](../src/components/student-home.tsx) показывает в ближайшем занятии и строках дня только начало/окончание, дисциплину, вид занятия, аудиторию, корпус и короткую отметку изменения. ФИО преподавателей, объединённые группы/подгруппы и заглушка «Преподаватель уточняется» из кратких карточек убраны. Заголовок с собственной группой студента сохранён.

Преподаватели и группы остаются в модели ответа, API, БД и полном расписании. Ссылки по-прежнему ведут на соответствующую дату. Название «Учебный корпус А» в кратком представлении сокращается до «корпус А»; исходные данные не меняются. Общая функция подписи изменения сохраняет перенос/замену и в ближайшей паре, и в дневном списке; отмена и перенесённая исходная пара остаются зачёркнутыми с прежней смысловой индикацией.

В [dashboard-home.css](../src/app/dashboard-home.css) уменьшены вертикальные отступы календаря, ближайшей пары и строк дня. Размеры текста и зелёные маркеры сохранены в обеих темах.

## Свободный порядок

Все четыре блока рендерятся одним проходом по сохранённому `layout.order`. На ПК используется сетка из двух равных колонок с обычным порядком по строкам: слева направо, затем следующая строка. Ниже 1100 px — одна колонка сверху вниз. Отдельной основной колонки расписания и отдельной группы вторичных блоков больше нет. CSS `order`, плотное заполнение пустых мест и размещение по именованным областям не используются: порядок DOM, клавиатурного обхода и визуального чтения совпадает.

У расписания обычные кнопки выше/ниже, как у остальных блоков. На первой/последней позиции недоступно только соответствующее направление. Его чекбокс остаётся отмеченным и недоступным: скрыть расписание нельзя. Стандартный порядок прежний: расписание → уведомления → учёба/контроль → объявления. Сброс возвращает этот порядок и видимость дополнительных блоков после сохранения.

[DashboardLayout](../src/lib/dashboard-layout.ts) больше не требует `order[0] === "schedule"`. Все остальные условия сохранены: ровно четыре допустимых уникальных ID; известные уникальные скрытые ID; запрет скрытия расписания; запрет лишних полей. Старые JSON-раскладки с расписанием первым полностью совместимы и не требуют переписывания.

[API](../src/app/api/dashboard/route.ts), [проверка владельца, роли и версии](../src/lib/dashboard-settings.ts) и модель `UserPreferences` не менялись. Сохранение остаётся в настройках аккаунта с compare-and-swap; конфликт возвращает 409. F5, повторный вход и смена ширины экрана сохраняют порядок. Новых миграций, зависимостей и хранилищ нет; академические данные в `localStorage` не помещаются.

## Проверки

[test:dashboard](../scripts/verify-dashboard.mjs) дополнен проверками:

- Все позиции расписания разрешены серверным валидатором; дубликаты, пропуски, неизвестные ID/поля, скрытое расписание и некорректные версии отклоняются.
- Старые JSON-настройки и существующая строка версии 7 читаются без миграции; права всех пяти ролей, анонимный доступ, владельцы и конфликт версий проверяются прежними сценариями.
- Через настоящий диалог расписание перемещается на второе, третье и последнее место, затем вверх; после F5 и повторного входа порядок сохраняется. Проверяются сброс, отмена и сохранённая серверная раскладка.
- На 346, 360 и 1366 px в обеих темах фактический порядок координат карточек сравнивается с DOM и сохранённым порядком; горизонтальное переполнение запрещено. Дополнительно сохранён проход 768 px.
- В кратком расписании отсутствуют имена преподавателей и названия совмещённых групп из реальной тестовой модели; время и аудитория сохранены. Перенос, замена и отмена проверяются отдельными сценариями. После перехода в полное расписание проверяется наличие преподавателя и совмещённой группы.

Тесты работают на изолированных БД со случайными временными паролями. Исходная рабочая БД проверяется полным отпечатком. Для временных визуальных сценариев используются DTO этой же тестовой БД; сохранение настроек проверяется настоящими запросами. Снимки `home-*`, `settings-*`, `scenario-*`, `order-{2,3,4}-{light,dark}-{346,360,1366}.png` сохраняются рядом с результатами в `.local/dashboard-test-*`.

Фактически прошли `npm run typecheck`, `npm run lint`, `npm run build`, `npm run test:dashboard` в dev и production, `npm run test:schedule:browser`, `npm run test:notifications`, `npm run test:auth` и `npm run test:auth:navigation` в dev и production. В браузере нет ошибок гидратации, Blocking Route/Instant или runtime; рабочая БД не изменилась. Снимки проверены визуально, включая мобильные размеры, диалог, замену занятия и расписание на последнем месте. Тема на снимках перестановок устанавливается до перезагрузки, чтобы не фиксировать промежуточные цвета CSS-перехода.
