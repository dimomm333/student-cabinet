# Расписание: интерфейс и интеграция кабинетов

Отчёт от 13 ноября 2026 года. Работа продолжает существующий проект и общий серверный слой расписания. Публичный API и следующие модули не добавлялись. Код авторизации, политика сессий и исправления безопасности не изменялись.

## Реализованное поведение

- На публичной странице работают подсказки непосредственно под полем поиска. Выбор доступен мышью, касанием, стрелками и Enter; Escape закрывает список. Фокус остаётся в поле, присутствуют label, combobox, listbox, option, aria-expanded, aria-controls, aria-activedescendant и сообщение о пустом результате.
- Клиент и сервер используют одну функцию нормализации и фильтрации. Кириллица регистронезависима, пробелы по краям игнорируются, `ё` и `е` считаются равными. Проверены `см7`, `СМ7`, `См7`, варианты ФИО и запросы с пробелами/табуляцией.
- Публичный справочник загружается вместе со страницей. Ввод текста не вызывает сетевых запросов. В подсказках отображаются первые 50 совпадений с предложением уточнить запрос; полный справочник доступен отдельно.
- Полный список групп сворачивается по структуре факультет → кафедра → направление → группа → подгруппы. Направление берётся из существующего поля `programme`. Пока принадлежность факультету/кафедре не заполнена, показаны честные категории «Факультет не указан» и «Кафедра не указана».
- Дни, соседние недели, выбор номера и даты используют навигацию Next.js с отключённым автоматическим скроллом. Полной перезагрузки нет, URL и история браузера сохраняются. Предзагрузка множества вариантов расписания отключена.
- Номер недели относится к конкретному опубликованному `AcademicTerm`. Неделя №1 — календарная неделя, содержащая `startsOn`; первая и последняя недели могут быть неполными. Переход через Новый год не сбрасывает нумерацию. Каждый период в списке имеет название и даты. При совпадении недель разных периодов параметр `term` сохраняет выбранный период.
- Дата в URL является источником выбранной недели; номер и диапазон вычисляются из неё. Произвольная дата приводится к понедельнику. Вне периода отображается соответствующее сообщение, доступен переход к текущей неделе.
- Числитель/знаменатель по-прежнему рассчитываются от `firstNumeratorMonday`, независимо от номера недели. Занятия за границами периода не отображаются.
- «Сегодня» вычисляется в `Europe/Moscow`. В навигации день выделен янтарным цветом и подписью, выбранный день — тёмно-зелёным. Совпадение состояний имеет отдельную янтарную отметку. На другой неделе сегодняшняя дата не выделяется. Карточка текущего дня также имеет подпись.

## Кабинеты и границы доступа

Страница студента: `/dashboard/schedule`. Группа определяется только по `StudentProfile.group`, а не по текстовому `groupName` или пользовательским параметрам. Если связи нет, показано сообщение для обращения в учебную часть. Для подгруппы добавляются общие занятия родителей; для группы — занятия её подгрупп. Занятия соседних подгрупп в расписание отдельной подгруппы не добавляются.

На главной студента счётчик занятий за сегодня и блок ближайших занятий читаются из БД. Блок показывает ближайший день с ещё не завершившимися занятиями в пределах 14 дней; горизонт поиска явно подписан. Используется общая карточка дня и занятия. В баннере при наличии связи отображается код фактической группы.

Страница преподавателя: `/teacher/schedule`. Сервер находит `TeacherProfile` по текущему аккаунту и выбирает занятия через `LessonTeacher.teacherId`. Видны его дисциплины, все связанные группы, аудитории, корпуса и время.

Обе страницы используют `requireRole` близко к чтению данных. Из URL принимаются только календарные параметры `week`, `day`, `term`; `group`, `teacher`, `userId`, `view`, поисковый запрос и прочие способы выбора владельца не участвуют в определении персонального расписания. Закрытый кабинет не предоставляет справочник других пользователей.

Все роли используют одни `Lesson`, `LessonGroup`, `LessonTeacher`, `ScheduleEntry`, `Room`, `Building` и `AcademicTerm`. Публичное расписание сохраняет прежние строгие фильтры публикации, включая сокрытие всего занятия при непубличном участнике/группе/аудитории/корпусе. В кабинете доступны опубликованные занятия, связанные с его владельцем, в том числе когда его профиль или группа не опубликованы для всех. Закрытые ФИО других преподавателей не включаются в DTO; студенческие списки, email, ID аккаунтов, сессии и пароли не передаются.

## Схема и сохранность базы

Добавлена одна таблица `AcademicDepartment` с названием кафедры и факультетом как категорией. Отдельная сущность факультета пока не нужна. `StudyGroup.departmentId` хранит необязательную реальную связь, `StudyGroup.parentId` — необязательную связь с родительской группой. Удаление связанной записи устанавливает NULL; существующие направления сохранены.

Новая миграция использует CREATE TABLE и ALTER TABLE ADD COLUMN; сброса или пересоздания существующих таблиц нет. Существующие группы никому не приписывались. Их новые поля остаются NULL. Seed основной базы повторно не запускался.

Перед миграцией создана согласованная копия SQLite через VACUUM INTO и снимок всех 18 прежних прикладных таблиц. После миграции и тестов сравнены все прежние поля и строки: изменений нет. `PRAGMA integrity_check` вернул `ok`, `PRAGMA foreign_key_check` не обнаружил нарушений. Все четыре миграции применены.

Локальная резервная копия расположена в `.local/schedule-upgrade/before.db`. Снимок и проверка находятся рядом; они игнорируются Git и содержат локальные данные, публиковать их не следует.

## Самостоятельная проверка

На текущем рабочем месте новая миграция уже применена. Для другого существующего экземпляра сначала сделайте согласованную резервную копию SQLite, затем выполните `npm.cmd ci`, `npm.cmd run db:generate`, `npm.cmd run db:deploy`. Сброс базы не нужен. Для этой доработки повторный seed не требуется.

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run build
npm.cmd run test
npm.cmd run test:auth
npm.cmd run test:schedule:browser
npm.cmd run db:status
```

Браузерный тест запускает собственный production-сервер на `127.0.0.1:3204`, использует временную копию SQLite и временные пароли. Нужен установленный Google Chrome. Для установленного Edge перед командой задайте `$env:PLAYWRIGHT_CHANNEL = 'msedge'`. Основная база, её пароли и сессии тестом не изменяются. Запускайте команду после production build; порт 3204 должен быть свободен.

Для ручной проверки запустите `npm.cmd run dev`:

1. Откройте `/schedule?group=pi-24-1&week=2026-11-09`. Введите `  пИ-24  `, выберите подсказку мышью и клавиатурой. В режиме преподавателя сравните `белова`, `БЕЛОВА`, `  БеЛоВа  `. Введите несуществующее имя, проверьте сообщение и Escape. Запрос `см7` ищется без учёта регистра, но не создаёт отсутствующую в основной БД группу.
2. Откройте «Все учебные группы», сверните факультет/кафедру/направление. ПИ-24-1 и ПИ-24-2 находятся под одним настоящим направлением. Отсутствие данных о факультете показано явно. Демоподгруппы в основной базе не создавались; реальная связь подгруппы проверяется автоматическим тестом на копии.
3. Прокрутите до дней. Переключайте день и соседнюю неделю: страница не должна уходить вверх. Проверьте «Назад»/«Вперёд». Выберите неделю №1: начало 31.08.2026. Выберите 09.11.2026: неделя №11. На неделе 09.11 — числитель, 16.11 — знаменатель. Вне опубликованного периода занятий нет.
4. Нажмите «Текущая неделя»: сегодняшняя дата отмечена по Москве. На следующей неделе отметки нет. Выбранный день отличается от сегодняшнего цветом и подписью.
5. Войдите студентом и откройте `/dashboard`, затем `/dashboard/schedule`. Сверьте группу с профилем; в основной демобазе оба студента пока принадлежат ПИ-24-1. Добавьте к URL `group=it-25-1&teacher=anna-belova&userId=foreign`: персональное расписание не меняется.
6. Войдите Михаилом Соколовым и откройте `/teacher/schedule?week=2026-11-09`: видны его занятия по всем трём группам, но не чужие занятия. Проверьте те же попытки подмены URL и отказ доступа к кабинету другой роли.
7. Повторите поиск, касания, дни, недели и историю на телефоне или в эмуляции ширины 390 px. Горизонтально прокручивается только полоса дней, страница не переполняется.

Для повторной проверки сохранности текущей базы относительно снимка перед миграцией: `node --env-file-if-exists=.env scripts/preserve-schedule-database.mjs`. После законных изменений данных этот старый снимок ожидаемо перестанет совпадать; не используйте его как проверку новых изменений.
