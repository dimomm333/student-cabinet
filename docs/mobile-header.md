# Автоматическое скрытие мобильной верхней панели

Общий [AutoHideHeader](../src/components/auto-hide-header.tsx) используется в [DashboardShell](../src/components/dashboard-shell.tsx) и [WorkspaceShell](../src/components/workspace-shell.tsx), то есть во всех пяти кабинетах. Публичная шапка не меняется.

## Поведение

- На существующем мобильном breakpoint до 760 px панель остаётся `sticky` у верхнего края. После движения вниз на 32 px она уезжает вверх; после движения вверх на 14 px возвращается. Отсчёт ведётся от локального минимума/максимума прокрутки, поэтому небольшие колебания не переключают состояние постоянно.
- В начале страницы панель всегда видна. Смена страницы, переход по ссылке с параметрами, история браузера и изменение ширины возвращают её в видимое состояние.
- Скрытие использует только `transform`: высота панели остаётся в потоке, содержимое не пересчитывается и код не записывает позицию прокрутки. Мобильный фон непрозрачен и использует существующие переменные поверхности, чтобы контент не просвечивал под кнопками.
- Для документа кабинета и потенциального собственного scroll-container задан мобильный `scroll-padding-top: 84px`. Нативный переход фокуса и `scrollIntoView` оставляют место под панелью; регрессия проверяет поле, которое до фокуса находилось у верхнего края под скрытой шапкой.
- При скрытии панель получает `inert`, чтобы невидимые кнопки не попадали в клавиатурный обход. Нажатие клавиши раскрывает её до дальнейшего взаимодействия. Открытый dropdown в панели, любой открытый `dialog`, фокус в поле/форме и уменьшение видимой области под экранную клавиатуру удерживают панель видимой.
- Слушатели жестов пассивные. Программная прокрутка при фокусе или восстановлении истории не запускает скрытие. Изменение высоты содержимого сбрасывает отсчёт движения, чтобы scroll anchoring при загрузке или раскрытии секции не считался свайпом.
- При `prefers-reduced-motion: reduce` действующее общее правило отключает transition; скрытие и показ происходят без анимации.
- Небольшое изменение высоты viewport при движении адресной строки браузера сохраняет видимость панели. Ширина/ориентация и крупное изменение высоты под экранную клавиатуру раскрывают её.
- На desktop сохраняется прежняя статическая панель.

## Контейнер прокрутки

У текущих оболочек `.dashboard-workspace` и `.dashboard-main` нет собственного вертикального overflow. Страницу прокручивает `document.scrollingElement` (`HTML` в проверенном Chrome). Боковое меню, таблицы, календари и некоторые списки имеют независимые области прокрутки.

Компонент определяет ближайшего прокручиваемого предка панели по `overflow-y`; если его нет, использует `document.scrollingElement`. События прокрутки вложенных таблиц, полей, календарей и списков не управляют панелью. При смене контейнера отсчёт сбрасывается. Отдельная регрессия проверяет прокрутку внутри `.dashboard-workspace` при нулевом `window.scrollY`.

## Проверка

[verify-mobile-header.mjs](../scripts/verify-mobile-header.mjs) использует новую изолированную БД, временный пароль, фиктивные длинные материалы и свободный порт. Основная БД сравнивается до и после. Для dev создаётся отдельная копия проекта и отдельный кеш Next.js.

```sh
npm run typecheck
npm run lint
npm run build
npm run test:header
npm run test:header -- --development
npm run test:auth
npm run test:auth:navigation
npm run test:auth:navigation -- --production
```

Целевая матрица: профиль, услуги, материалы, БРС и расписание студента; профили остальных четырёх ролей; 346, 360, 390 и 1366 px. Проверяются скрытие и возврат, мелкие колебания, сохранение высоты документа и координат контента, достижимость кнопок, формы и видимость поля после фокуса, меню темы, боковое меню, реальный диалог БРС, переходы Next.js без перезагрузки, back/forward, параметры расписания, вложенная прокрутка, touch-свайп через Chrome DevTools Protocol, уменьшенная высота viewport, небольшие изменения высоты под адресную строку и reduced motion. Снимки сохраняются в игнорируемом `.local`.

Экранная клавиатура проверяется через фокус реального текстового поля и уменьшение viewport; нативная клавиатура физических iOS/Android устройств в headless Chrome не воспроизводится. Firefox, Safari и физические устройства отдельно не проверены.
