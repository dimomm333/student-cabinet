# Публичный REST API расписания v1

API работает в существующем приложении Next.js, без отдельного сервера. Базовый путь — `/api/v1`. Внешние приложения обращаются к HTTPS-адресу университета. Локальные примеры: `http://localhost:3000`.

Редактор деканата добавляет необязательное поле `lesson.change` для разовых замен, переносов, отмен и дополнительных пар. Прежние поля и их типы сохраняются. Карточки с `change.cancelled === true` не являются активными занятиями. Формат, граница публикации исходных данных и обновление кеша описаны в [документации редактора](./schedule-editor.md#синхронизация-и-api-v1).

Все сведения вымышлены. API публикует только разрешённые к публикации группы, имена преподавателей и занятия. Авторизация для чтения не нужна. Cookie авторизации не расширяет набор доступных данных.

## Формат и совместимость

- Ответы — JSON UTF-8; версия контракта определяется `/api/v1/` и `meta.apiVersion`.
- Публичные идентификаторы — `slug` группы/преподавателя и `code` учебного периода. Это не ID пользователей, профилей или сессий.
- Календарные даты: `YYYY-MM-DD`, поддерживается диапазон 2000–2099. Расписание использует `Europe/Moscow` независимо от часового пояса клиента.
- Начало и конец занятия: `HH:mm`, минуты московского учебного дня; `24:00` допустимо только как конец дня.
- Метаданные `generatedAt` и `expiresAt` — ISO 8601 в UTC с `Z`. Они описывают начало выборки и срок её серверного кеша.
- Перечисления `kind`, `weekPattern`, `parity` возвращаются стабильными машинными кодами. Сообщения об ошибках предназначены для человека; приложение должно проверять `error.code`.
- Дополнительные поля ответа могут добавляться в v1. Изменение значения существующего поля или его типа требует новой версии контракта. Клиентам следует игнорировать незнакомые поля ответа.
- Неизвестные или повторяющиеся параметры запроса отклоняются, чтобы ошибки интеграции не оставались незаметными.

## GET /api/v1/schedule

Ровно один из параметров `group` или `teacher` обязателен. Значения берутся из соответствующих справочников API.

| Параметр | Тип | Назначение |
| --- | --- | --- |
| `group` | string | Публичный slug группы; несовместим с `teacher` |
| `teacher` | string | Публичный slug преподавателя; несовместим с `group` |
| `week` | YYYY-MM-DD | Любой день нужной недели; приводится к понедельнику. Без выбора недели используется текущая неделя по Москве |
| `weekNumber` | integer 1–104 | Порядковый номер недели в `term`; реальная верхняя граница определяется периодом |
| `term` | string | Код опубликованного учебного периода; обязателен для `weekNumber` |

Slug и код периода: от 1 до 64 символов `a-z`, `0-9`, `-`. `week` и `weekNumber` вместе запрещены. При `week` + `term` неделя должна пересекаться с указанным периодом.

Нумерация использует общий календарь сайта: неделя №1 содержит дату начала периода, поэтому первая и последняя недели могут быть неполными. Через Новый год нумерация продолжается. Числитель/знаменатель считаются отдельно от номера недели — относительно `firstNumeratorMonday` существующего календаря. Неполная первая неделя не создаёт занятия до фактического начала периода.

`term` задаёт календарь нумерации. Как и на сайте, ответ включает все опубликованные занятия выбранного владельца в календарной неделе с учётом границ каждого периода. Если периоды перекрываются, каждый урок содержит свой `term`, а `week.periods` — соответствующие номера и чётности. Этот параметр не скрывает занятия других действующих в ту же неделю периодов.

Примеры:

```bash
curl 'http://localhost:3000/api/v1/schedule?group=pi-24-1&week=2026-11-09'
curl 'http://localhost:3000/api/v1/schedule?teacher=mikhail-sokolov&week=2026-11-09'
curl 'http://localhost:3000/api/v1/schedule?group=pi-24-1&term=demo-autumn-2026&weekNumber=11'
```

Фрагмент ответа: для краткости показан один день и одно занятие. Полный ответ всегда содержит семь дней и все возвращаемые занятия, в том числе дни с `lessons: []`.

Коды периодов можно получить из `data.week.periods` известной недели расписания. Отдельного API учебных периодов в этом этапе нет. Если в текущей неделе опубликованных периодов нет, выберите дату известного учебного периода либо используйте код, предоставленный университетом.

Существующая публичная группа/преподаватель с пустой неделей получает `200`, семь пустых дней и `truncated: false`. Отсутствующая или непубличная группа/преподаватель получает одинаковый `404`. Вне опубликованных периодов можно запросить неделю без `term`: это пустое расписание, а не серверная ошибка.

## GET /api/v1/groups

| Параметр | Значение по умолчанию | Ограничения |
| --- | --- | --- |
| `q` | пустая строка | До 80 символов до удаления пробелов по краям |
| `limit` | 50 | Целое число 1–100 |
| `offset` | 0 | Целое число 0–5000 |

Поиск не учитывает регистр кириллицы, пробелы по краям и различие `ё`/`е`. Используется общий с сайтом поиск по названию, slug и направлению. `см7`, `СМ7` и `  См7  ` эквивалентны, если такая группа есть в опубликованных данных.

```bash
curl 'http://localhost:3000/api/v1/groups?q=%D0%BF%D0%B8-24&limit=10&offset=0'
```

```json
{
  "data": [
    {
      "slug": "pi-24-1",
      "name": "ПИ-24-1",
      "programme": "Прикладная информатика",
      "faculty": null,
      "department": null,
      "parentSlug": null
    },
    {
      "slug": "pi-24-2",
      "name": "ПИ-24-2",
      "programme": "Прикладная информатика",
      "faculty": null,
      "department": null,
      "parentSlug": null
    }
  ],
  "pagination": {
    "limit": 10,
    "offset": 0,
    "total": 2,
    "hasMore": false,
    "nextOffset": null
  },
  "meta": {
    "apiVersion": "v1",
    "generatedAt": "2026-11-13T12:00:00.000Z",
    "expiresAt": "2026-11-13T12:00:15.000Z"
  }
}
```

`faculty` и `department` берутся из настоящей связи с кафедрой; незаполненные значения — `null`. `parentSlug` указывает на публичную родительскую группу, если она есть. Для непубличного родителя поле равно `null`, чтобы не раскрывать его идентификатор. Дерево можно построить, собрав страницы и связав записи по `parentSlug`; родитель может находиться на другой странице. Принадлежность к факультету по префиксу группы не вычисляется.

Порядок — по коду группы, затем slug. Изменения справочника между запросами могут менять страницы: это offset-пагинация, а не снимок на всё время обхода. При отсутствии совпадений или при offset за концом — `200`, `data: []`, `hasMore: false`.

## GET /api/v1/teachers

Параметры и пагинация такие же, как у групп. Поиск — по публичному ФИО и slug, с той же нормализацией регистра и пробелов. Порядок — по публичному имени, затем slug.

```bash
curl 'http://localhost:3000/api/v1/teachers?q=%D0%91%D0%B5%D0%BB%D0%BE%D0%B2%D0%B0&limit=10'
```

```json
{
  "data": [{ "slug": "anna-belova", "name": "Анна Белова" }],
  "pagination": { "limit": 10, "offset": 0, "total": 1, "hasMore": false, "nextOffset": null },
  "meta": {
    "apiVersion": "v1",
    "generatedAt": "2026-11-13T12:00:00.000Z",
    "expiresAt": "2026-11-13T12:00:15.000Z"
  }
}
```

Email, имя аккаунта из User, ID авторизации, студенческие списки, оценки, credentials, токены и сессии не возвращаются. Источник имени — только разрешённое к публикации `TeacherProfile.publicName`.

## Ошибки и HTTP

```json
{
  "error": {
    "code": "INVALID_PARAMETERS",
    "message": "Для weekNumber требуется term."
  }
}
```

| Статус | Код | Смысл |
| --- | --- | --- |
| 200 | — | Расписание/справочник, включая пустой результат |
| 204 | — | `OPTIONS`, заголовок `Allow: GET, HEAD, OPTIONS` |
| 304 | — | Совпавший `If-None-Match`; тела нет |
| 400 | `INVALID_PARAMETERS` | Неизвестные/повторные параметры, несовместимые параметры, неверные типы, длина, дата или slug |
| 400 | `INVALID_WEEK_NUMBER` | Номер за фактической границей периода |
| 400 | `WEEK_OUTSIDE_TERM` | Дата не входит в указанный период |
| 403 | `UNTRUSTED_PROXY` | Нет доверенного proxy при включённом доверенном режиме либо неверный секрет/IP |
| 404 | `SELECTION_NOT_FOUND` | Группа/преподаватель отсутствуют или непубличны |
| 404 | `TERM_NOT_FOUND` | Период отсутствует или не опубликован |
| 405 | `METHOD_NOT_ALLOWED` | POST, PUT, PATCH, DELETE запрещены; БД не меняется |
| 429 | `RATE_LIMITED` | Превышен бюджет запросов; есть `Retry-After` в секундах |
| 503 | `API_BUSY` | Заняты все слоты загрузки данных |
| 503 | `API_TIMEOUT` | Ожидание ответа превысило 10 секунд |
| 503 | `CATALOG_CAPACITY` | Публичный справочник превысил текущий предел обработки |
| 503 | `UNSUPPORTED_TIME_ZONE` | У занятия указан иной пояс: API не переименовывает местное время в московское |
| 503 | `API_UNAVAILABLE` | Недоступна БД или некорректна серверная конфигурация |

У `503` также есть `Retry-After`. Ошибки имеют `Cache-Control: no-store`; внутренние SQL-ошибки, пути файлов и stack trace в ответ не включаются. Ошибки инфраструктуры до вызова Next.js могут иметь собственный формат.

`HEAD` проходит те же лимиты и проверки, что GET, но не возвращает тело. `OPTIONS` не читает БД и не разрешает изменение. CORS-заголовки не добавляются, в том числе для OPTIONS: браузерное приложение с другого origin не получает автоматического доступа. Серверные интеграции и нативные приложения могут обращаться к API по HTTPS. Для будущей веб-интеграции необходимо отдельно согласовать список разрешённых origin.

## Частота, нагрузка и кеш

Все GET/HEAD, включая некорректные запросы и условные запросы, проходят контроль до чтения кеша или БД. Настройки задаются окружением:

| Переменная | По умолчанию | Допустимые значения |
| --- | --- | --- |
| `SCHEDULE_API_RATE_LIMIT` | 60 | 1–10000 запросов на подтверждённый IP за фиксированные 60 секунд |
| `SCHEDULE_API_GLOBAL_LIMIT` | 600 | 1–100000 запросов суммарно за фиксированные 60 секунд |
| `SCHEDULE_API_CONCURRENCY` | 4 | 1–32 одновременно выполняемых загрузок из БД |
| `SCHEDULE_API_CACHE_SECONDS` | 15 | 0–60; 0 отключает серверное хранение ответов |

Лимиты общие для трёх endpoints внутри одного процесса Node.js. Окно начинается с первого запроса; отказ не продлевает окно. Состояние хранится в ограниченной памяти, не пишет в БД и сбрасывается при перезапуске. Хранятся хеши IP, а не сами адреса. Вместимость таблицы бюджетов — 4096 записей; при её заполнении новые адреса получают 429 до освобождения истёкших окон.

Применяется существующая архитектура `AUTH_TRUST_PROXY` / `AUTH_PROXY_SECRET`:

- При `AUTH_TRUST_PROXY=false` разрешён существующий локальный режим; все клиенты используют один общий бюджет. Клиентские `X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `X-Lks-Verified-IP` не дают отдельного бюджета.
- Для внешнего HTTPS-адреса требуется `AUTH_TRUST_PROXY=true`. Reverse proxy должен перезаписывать `X-Lks-Proxy-Key` своим секретом и `X-Lks-Client-IP` проверенным единственным IP. Передавать эти значения непосредственно от клиента нельзя. Проверка подписи proxy-ключа использует существующее сравнение с постоянным временем; списки IP и невалидные IP отклоняются.
- Порт Node.js на VPS должен быть закрыт от внешних прямых подключений. Proxy-ключ не передаётся Telegram-ботам, мобильным клиентам или браузеру: его добавляет только ваш reverse proxy.
- Для нескольких workers/реплик дополнительно нужен общий лимит на reverse proxy/API gateway. Эти локальные ограничения не являются распределённым rate limiter. Там же задайте ограничения URL/заголовков, соединений и upstream timeout.

Дополнительные пределы: строка query до 2048 символов; страница до 100 записей; до 5000 публичных групп и 5000 публичных преподавателей в обрабатываемом справочнике. Для совместимого поиска кириллицы используется общий поиск сайта после ограниченного чтения справочника. Превышение ёмкости возвращает 503, а не тихо неполный список. Перед ростом выше этих пределов потребуется отдельная доработка поиска/индексации.

Одновременно идут не более четырёх загрузок по умолчанию. Совпадающие запросы делят одну выполняемую загрузку. Новые уникальные запросы при занятых слотах получают 503. HTTP-ожидание ограничено 10 секундами; уже запущенный запрос БД может завершиться позднее, продолжая занимать слот, чтобы не запускать новые тяжёлые запросы поверх него.

Кеш содержит только окончательные публичные JSON-ответы: максимум 128 записей, фиксированный TTL, без продления при чтении. Неудачные загрузки не кешируются. Ключ канонизирует дату до понедельника и не содержит cookie, токены или заголовки авторизации. `ETag` вычислен по телу ответа; сервер отвечает 304 при совпадении. Ответы имеют `Cache-Control: public, max-age=0, must-revalidate`: внешнему кешу требуется повторная проверка, которая снова проходит лимиты и proxy-проверку.

По истечении TTL данные перечитываются, включая изменения и снятие с публикации. До истечения TTL предыдущий публичный снимок может ещё возвращаться; при стандартных настройках устаревание ограничено 15 секундами от начала загрузки. Нет дополнительного `stale-while-revalidate`. Для будущих авторизованных операций редактирования предусмотрена внутренняя `invalidateScheduleApiCache()` после фиксации изменений; публичного endpoint инвалидации нет. Для нескольких процессов инвалидацию надо выполнять в каждом процессе либо полагаться на короткий TTL. Перезапуск процесса также очищает кеш.

## Архитектура и границы публикации

Route Handlers в существующем Next.js → общий API-адаптер/валидация/контроль нагрузки → существующий серверный репозиторий расписания → Prisma. Нет отдельной БД, второго сервера или второго алгоритма расчёта недель.

Сайт и API используют общие `getPublicScheduleCatalog`, `getPublicScheduleData`, `academicWeeks`, `weekParity`, `filterScheduleChoices`. API формирует собственную явную проекцию с машинными enum-кодами, не раскрывает внутренние ключи карточек и не обращается к персональному серверному слою.

Сохранены прежние строгие фильтры публикации: скрыто занятие с непубличной группой или соучаствующим преподавателем, непубличной аудиторией/корпусом, неопубликованным периодом или записью. Общие занятия наследуются по настоящим связям групп и подгрупп. Если кандидатных записей больше 300, возвращаются первые 300 по дню/времени с `data.truncated: true`; интеграция должна явно показать ограничение пользователю.

API не меняет БД, включая служебные лимиты. Для него не добавлялись таблицы или миграции. Новые запросы используют Prisma, без SQLite-специфичного SQL и абсолютных путей. Имеющийся адаптер подключения SQLite остаётся общей точкой будущего перехода на PostgreSQL. Код авторизации и SEC-01/02/03 не менялись.

В дополнительном dev-прогоне обнаружено предупреждение Instant на первом открытии `/staff/requests`: `await params` общего компонента разделов не имел собственной границы в текущей области навигации. Для сохранения корректных кабинетов добавлен внутренний Suspense вокруг содержимого `WorkspaceSection`. Проверки прав и внешний вид загруженного раздела сохранены, диагностика и Cache Components не отключались.

## Telegram и мобильные приложения

### Telegram-бот

Сервер бота сначала ищет группу/преподавателя, предлагает пользователю публичные варианты, сохраняет выбранный slug и запрашивает нужную неделю. Используйте webhook/планировщик бота; отдельный API-сервер университета не нужен. Не сохраняйте пароли ЛКС: публичный API их не требует.

Запрашивайте один снимок на общую комбинацию владельца и недели, распределяйте его подписчикам. Для уведомлений о занятиях учитывайте дату дня, `start` и `Europe/Moscow`. При 429/503 ждите `Retry-After`, добавляйте случайную задержку повторов; не повторяйте автоматически 400/404 без исправления выбора.

### Мобильное приложение

Нативный клиент использует HTTPS, пагинацию справочников и публичные slug. Можно локально хранить последнюю успешную неделю для offline-режима с заметной датой актуальности. Обновляйте по TTL и сохраняйте `ETag` для `If-None-Match`; 304 означает использование прежнего тела. При 200 заменяйте весь снимок недели.

Минимальный JavaScript-пример для серверной или нативной среды:

```js
async function loadSchedule(baseURL, group, week, previous = {}) {
  const url = new URL('/api/v1/schedule', baseURL);
  url.searchParams.set('group', group);
  url.searchParams.set('week', week);
  const response = await fetch(url, {
    headers: previous.etag ? { 'If-None-Match': previous.etag } : {},
  });
  if (response.status === 304) return previous;
  if (!response.ok) {
    const { error } = await response.json();
    throw new Error(`${response.status}: ${error.code}`);
  }
  return { etag: response.headers.get('ETag'), body: await response.json() };
}

const snapshot = await loadSchedule(process.env.LKS_BASE_URL, 'pi-24-1', '2026-11-09');
console.log(snapshot.body.data.days);
```

При повторном запросе той же группы/недели передайте `snapshot` последним аргументом. В мобильном приложении базовый URL задаётся его конфигурацией, а не `process.env`. Этот пример не снимает ограничения CORS для произвольной веб-страницы.
